# 设备连接兼容增强（opensvr）设计文档

- 日期：2026-07-07
- 状态：已定稿（用户明确授权"你来定"，按推荐方案实施）
- 第一原则：**实用、轻量、资源占用低**；一切以"现场设备能不能连上"为准绳。

## 1. 背景与目标

opensvr 已实现 FTP/SFTP/TFTP 三协议、双主机密钥、老设备兼容算法、被动端口段、
一键放行防火墙等。本轮针对**对比商业/开源同类软件（Tftpd64、Serva、3CDaemon、
FileZilla Server、Serv-U）后仍存在、且直接影响"设备能否连上"的兼容性缺口**做增强。

目标（第一档：设备连接兼容）：
1. **移除 Web「SFTP 主机密钥」卡片** —— 现场开局用不到（指纹核对是安全敏感场景防
   中间人的；开局设备普遍首连直接接受），删掉减少干扰。
2. **SCP 支持** —— 覆盖只走 SCP 的设备（思科 `copy scp:`、部分华为/H3C 老机型）。
3. **「设备该连哪个 IP」引导** —— 多网卡（WiFi+网线+VPN）时告诉外行该用哪个地址。
4. **防火墙自动放行 + 退出清理** —— 减少手动步骤，避免规则堆积。

### 不做（YAGNI，需要再单独提）
FTPS、SFTP 公钥认证、SCP 目录递归（`-r`）、绑定指定网卡、DHCP/PXE/BOOTP(ZTP)、
内置 Syslog。

### 2.2 SCP 支持（核心）

**现状问题**：`internal/sftpsrv/sftpsrv.go` 的 `handleConn` 对每个 channel 只接受
`subsystem sftp` 请求，`exec` 请求一律 `Reply(false)` → 走 SCP 的设备无法连接。
`docs/USAGE.md` 目前只能让用户"改用 FTP/TFTP"兜底。

**方案选型**：

| 方案 | 结论 |
|---|---|
| A. 手写 SCP 协议（exec handler 内实现 source/sink，复用 vfs 囚笼） | **采用**：无新依赖、贴合现有裸 `x/crypto/ssh`+afero 架构、可控 |
| B. 引三方库（如 charmbracelet/wish/scp） | 否决：绑 `gliderlabs/ssh` 框架，与现有裸 ssh 不同，适配成本更高 |
| C. 外挂系统 `scp` | 否决：破坏单 exe 绿色便携 |

**架构改造**：`handleConn` 接受 channel 后，按请求类型分发（新增 `internal/sftpsrv/scp.go`）：

```
subsystem "sftp"        -> Reply(true)，起现有 sftp.RequestServer（不变）
exec "scp ..."          -> Reply(true)，起 SCP handler，跑完发 exit-status=0 关闭 channel
其它                     -> Reply(false)
```

**SCP 协议（rcp over ssh）要点**，只做**单文件双向**：

- 命令解析：从 `exec` payload（`req.Payload[4:]`）取命令串，解析标志与路径。
  - `-t <path>`：sink，**服务端接收**（设备上传，如 `copy flash:x scp://pc/y`）。
  - `-f <path>`：source，**服务端发送**（设备下载，如 `copy scp://pc/y flash:x`）。
  - 识别但不特殊处理：`-d`（目标为目录）、`-p`（保留时间）、`-v`；`-r`（递归）→ 明确报错拒绝。
  - 路径经 `path.Clean("/"+name)` 归一后走 `vfs.Fs()`（囚笼内），与 TFTP 一致。
- 控制报文（ASCII 行 + 二进制负载）：
  - `C<mode> <size> <name>\n`：文件头；`T.../D.../E`：时间/目录（本轮目录不支持）。
  - 应答字节：`\x00`=OK，`\x01`=警告+消息+`\n`，`\x02`=致命+消息+`\n`。
- **Sink（-t）流程**：发 `\x00` 就绪 → 读控制行 → 遇 `C` 应答 `\x00`、精确读 `size`
  字节写入 vfs、读客户端结尾 `\x00`、再应答 `\x00`；遇 `D` 报 `\x02` 拒绝（不支持目录）；
  channel EOF 结束。
- **Source（-f）流程**：读客户端 `\x00` → `Stat` 目标（目录且非 `-r` → `\x02` 拒绝）→
  发 `C0644 <size> <name>\n` → 读 `\x00` → 发 `size` 字节 → 发结尾 `\x00` → 读 `\x00` → 结束。
- 结束：`ch.SendRequest("exit-status", false, {Status:0})` 后关闭 channel。

**计量与会话**：传输字节经计数包装回填当前 SSH 会话（`sessions.AddBytes`），并更新
会话 `Action`（scp download/upload）与 `File`；底层 vfs 仍计入全局 metrics。复用
`handleConn` 已登记的 `sessID`。

**日志**：`logbus.Emit`（Proto:"sftp"，Action:"scp-read"/"scp-write"，含 OK 与路径）。

**安全**：路径穿越由 vfs 囚笼兜底（禁止越出根目录）；认证复用现有 `PasswordCallback`
（SCP 与 SFTP 共用同一 SSH 登录，认证一致）。

### 2.3 「设备该连哪个 IP」引导

**现状**：`/api/status` 已返回 `nics`（`netinfo.List()`：全部 up 非回环 IPv4），
前端罗列，但不引导。

**方案**：`netinfo` 增加**推荐排序/标记**，不改监听（三协议仍 `0.0.0.0` 全网卡），
纯展示引导，零风险：

- 新增 `NIC.Recommended bool` 与排序逻辑：
  - 排除 APIPA（`169.254.0.0/16`）。
  - 优先私网段（`192.168/16`、`10/8`、`172.16/12`）。
  - 按网卡名弱启发降低虚拟/隧道网卡优先级（名字含 `VMware/VirtualBox/Loopback/vEthernet/
    Hyper-V/TAP/VPN/Tailscale/ZeroTier/WSL` 等）。
  - 取排序后第一个私网、物理网卡标 `Recommended=true`（无私网则不标）。
- 前端在地址区高亮推荐项（如加"设备连这个 →"徽标），其余仍列出。

### 2.4 防火墙自动放行 + 退出清理

**现状**：手动点按钮 → `/api/firewall` → `netsh advfirewall firewall add`（需管理员）；
**从不删除**，规则会随每次点击/端口变更堆积。

**方案**：把防火墙操作抽为独立包 `internal/firewall`（便于单测命令构造），
提供 `Allow(rules)`、`Remove(names)`、`IsElevated()`；触发点绑定协议生命周期：

- **已提权**（进程以管理员运行）：某协议**成功启动**时（`manager.StartFTP/StartSFTP/
  StartTFTP`）自动 `Allow` 该协议端口（FTP 另加被动段）；**停止**时 `Remove` 同名规则
  （`netsh ... delete rule name=...`）。
- **未提权**：不自动操作；保留现有一键按钮；提示文案改为明确说明"需以管理员运行才能自动放行"。
- 幂等：`add` 前先按同名 `delete` 再 `add`，避免重复规则。
- 不主动触发 UAC（便携工具不做每次弹窗）。
- 提权检测：Windows 下尝试判断（如打开 `\\.\PHYSICALDRIVE0` 或调用 token API，
  实现时选最简可靠方式）。

## 3. 测试策略

沿用项目 TDD 与"无外部依赖、用 `x/crypto/ssh` 客户端驱动"的既有风格：

- **SCP**（`internal/sftpsrv/scp_test.go`）：ssh 客户端起 session、`Run("scp -t ...")`
  / `Run("scp -f ...")`，手动走 SCP 报文，双向端到端验证内容一致；含错误路径（不存在文件、
  目录被拒）。
- **netinfo**（`internal/netinfo/netinfo_test.go`）：喂入构造的 NIC 集，断言推荐排序
  规则（排除 APIPA、私网优先、虚拟网卡靠后）——将排序逻辑抽成可测纯函数。
- **防火墙**：把 `netsh` 命令构造抽成可测纯函数（校验 add/delete 参数），实际 `netsh`
  调用不在单测跑。
- **移除项**：删除对应测试；`go test ./...` 全绿。
- **回归**：`go build ./...`、`go vet`（除既有 COM 噪声）、重建 exe。
