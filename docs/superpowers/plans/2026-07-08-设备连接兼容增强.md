# 设备连接兼容增强（opensvr）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐 spec `2026-07-07-设备连接兼容增强` 的 4 项：①移除 Web「SFTP 主机密钥」卡片 ②SCP 支持（单文件双向）③「设备该连哪个 IP」引导 ④防火墙自动放行+退出清理。

**Architecture:** 沿用现有单进程分层架构，裸 `x/crypto/ssh` + afero vfs 囚笼。SCP 走 exec channel 手写 source/sink，复用 vfs；防火墙抽为 `internal/firewall` 独立包并以 `Controller` 接口注入 Manager（默认 Noop，提权时注入 Netsh，便于单测）；netinfo 增加纯函数推荐排序。

**Tech Stack:** Go 1.26；`golang.org/x/crypto/ssh`；`github.com/spf13/afero`；`os/exec`(netsh)；原生 HTML/CSS/JS。

## Global Constraints

- 目标平台：**Windows amd64**，单静态 exe，无 cgo（`CGO_ENABLED=0`），不新增第三方依赖。
- 第一原则：**实用、轻量、低资源占用**；一切以"现场设备能否连上"为准绳。
- 必须支持**中文路径/文件名**（SCP 用例含中文名）。
- TDD：先写失败测试→跑红→最小实现→跑绿→提交；提交信息中文 `feat:`/`refactor:`，提交到 `master`。
- 单测**不实际调用 netsh**、不依赖真实网卡/管理员权限（纯函数 + 注入 fake）。
- SCP 与 SFTP 共用同一 SSH 登录与 vfs 囚笼；路径穿越由 vfs 兜底。
